# Конфигурационное управление: вариант №26, этап 1

Минимальный графический прототип оболочки (REPL) для отдельной сдачи
первого этапа. Реализованы только заглушки `ls`, `cd` и команда `exit`.
Заглушки выводят имя команды и список аргументов. Они не читают файлы
и не меняют текущий каталог. VFS, CSV, JSON, параметры командной строки,
стартовые сценарии и команды следующих этапов здесь отсутствуют.

## Требования и запуск

Python 3.10+ с Tkinter, графическая среда. Сборка и сторонние пакеты
не требуются. Приложение запускается без параметров.

Из корня этой папки:

```powershell
python -m src.main
```

Windows: `.\run.bat`. Скрипт сначала ищет `.venv` в папке проекта,
затем использует `py -3`, а при отсутствии Python Launcher — `python`.
Linux/macOS: `sh run.sh`.

### Запуск кнопкой Run в PyCharm

1. Откройте папку `configuration-management-shell-stage1` через File → Open.
2. В Run → Edit Configurations добавьте конфигурацию Python.
3. Выберите **Module name** и введите `src.main`.
4. Поле **Parameters оставьте пустым**: удалите `--vfs vfs.csv`, если оно есть.
5. Working directory — корень этой новой папки.
6. Выберите рабочий Python с Tkinter и нажмите Run.

Настраиваемых параметров на этапе 1 нет. Приглашение фиксировано: `$ `.
Ввод выполняется в нижнем поле окна, запуск команды — Enter.

## Синтаксис команд

- `ls [-l] [ПУТЬ]`: заглушка, допускающая один путь и один флаг `-l`.
- `cd [ПУТЬ]`: заглушка, допускающая один путь или отсутствие аргументов.
- `exit`: завершение без аргументов.

Наличие пути на диске не проверяется: это именно заглушки первого этапа.
Неизвестные флаги и лишние аргументы отклоняются.
Кавычки и экранирование не обрабатываются, разделителем служит пробельный
символ. Пустой ввод ничего не выполняет. После ошибки можно вводить
следующую команду.


| Ввод | Ожидаемый результат |
| --- | --- |
| `ls` | `Команда: ls`, `Аргументы: []` |
| `ls -l /home` | `Команда: ls`, `Аргументы: ['-l', '/home']` |
| `cd` | `Команда: cd`, `Аргументы: []` |
| `cd /home` | `Команда: cd`, `Аргументы: ['/home']` |
| `  ls   /tmp  ` | `Команда: ls`, `Аргументы: ['/tmp']` |
| Пустая строка | Новая команда не выполняется |
| `unknown` | Ошибка: неизвестная команда |
| `ls -x` | Ошибка: неизвестный параметр |
| `ls -l -l` | Ошибка: повторный параметр |
| `ls /one /two` | Ошибка: неверные аргументы ls |
| `cd /one /two` | Ошибка: неверные аргументы cd |
| `cd -x` | Ошибка: неизвестный параметр |
| `exit extra` | Ошибка; окно остаётся открытым |
| `ls` | Успешная команда после ошибок |
| `exit` | Окно закрывается |

Это инструкция для живой демонстрации, а не автоматически исполняемый
сценарий: стартовые сценарии относятся ко второму этапу.

## Структура и функции

- `src/main.py`: `main` создаёт окно, подключает оболочку и запускает цикл
  событий; ошибка создания окна выводится в терминал с кодом завершения 1.
- `src/errors.py`: `EmulatorError` представляет ошибку команды.
- `src/shell.py`: `validate_ls` и `validate_cd` проверяют аргументы;
  `stub_output` формирует вывод заглушки. `ShellEmulator.__init__` задаёт
  приглашение и состояние, `window_title` читает данные ОС, `execute`
  разбирает строку и выбирает обработчик. `_cmd_ls` и `_cmd_cd` вызывают
  заглушки, `_cmd_exit` проверяет аргументы и выставляет флаг завершения.
- `src/gui.py`: `EmulatorGUI.__init__` создаёт окно; `_create_output` и
  `_create_input` создают журнал и поле ввода; `append` добавляет текст;
  `_on_enter` читает и очищает ввод; `run_command` отображает ввод, результат
  или ошибку и закрывает окно после `exit`.
- `tests/.gitkeep`: сохраняет пустую папку тестов для первого этапа.
- `run.bat`, `run.sh`: запуск из корня проекта.

Документация функций находится также в docstring. В этой сдаваемой версии
первого этапа автоматических тестов нет. Для проверки используется
интерактивная последовательность выше. Общая команда обнаружения тестов:

```powershell
python -m unittest discover -s tests -v
```

Она обнаружит 0 тестов, что ожидаемо для пустой папки первого этапа;
некоторые версии Python возвращают в этом случае ненулевой код.
