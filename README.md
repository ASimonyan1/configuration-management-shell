# Конфигурационное управление: вариант 26, этап 2

Отдельная сдача этапа «Конфигурация», страницы 83-84 задания.
Основа - графический REPL первого этапа. Реализованы настройки CLI/JSON,
отладочный вывод параметров и стартовые сценарии. Команды ls и cd остаются
заглушками; exit закрывает окно. Путь VFS хранится и выводится, но файл
не открывается: загрузка CSV и настоящие операции относятся к этапам 3-5.

## Требования и запуск

Python 3.10+ с Tkinter и графической средой. Сторонние пакеты не нужны.
Сборка не требуется. Все команды выполняются из корня проекта.

```powershell
python -m src.main
.\run.bat --config config.json
python -m src.main --vfs data/demo.csv --prompt "emu> " --script scripts/stage2.txt
python -m unittest discover -s tests -v
```

Linux/macOS: `sh run.sh --config config.json`.
Windows-скрипт ищет Python в `.venv`, затем `py -3`, затем `python`.
В PyCharm выберите рабочий Python с Tkinter, Module name `src.main`,
Working directory - корень проекта, Parameters `--config config.json`.
Команда без параметров также поддерживается: приглашение `$ `,
путь VFS и сценарий не заданы.

## Настройки

| CLI | Поле JSON | Назначение |
| --- | --- | --- |
| `--vfs` | `vfs` | Путь к физическому расположению VFS |
| `--prompt` | `prompt` | Приглашение к вводу |
| `--script` | `script` | Путь к стартовому сценарию |
| `--config` | нет | Путь к JSON-конфигурации |

```json
{
  "vfs": "data/from-json.csv",
  "prompt": "json> ",
  "script": "scripts/from_json.txt"
}
```

Сначала читается JSON, затем переданные значения CLI заменяют значения
JSON. Пустой `--prompt ""` тоже имеет приоритет. Неуказанные поля и null
считаются отсутствующими. При отсутствии prompt используется `$ `.
Относительные пути отсчитываются от рабочего каталога процесса.
Невалидный JSON, неверный тип поля, недоступный файл или ошибка кодировки
выводятся в терминал как ошибка запуска, код завершения 2; окно не открывается.
В окне показываются все четыре эффективных параметра. Приглашение выводится
через repr, чтобы различать пустую строку и пробелы.

## Стартовый сценарий и команды

UTF-8 файл: одна команда на строку. Пустые строки и отдельные строки
комментариев `# ...` (синтаксис Python), в том числе с отступом, пропускаются.
Комментарии после команды не поддерживаются. На экране отображаются ввод,
вывод и ошибки; шаги выполняются через Tkinter.after без блокирования окна.
После конца сценария доступен ручной ввод. Ошибка команды не останавливает
сценарий; exit без аргументов закрывает окно и прекращает сценарий.
Ошибка чтения сценария выводится в журнал, ручной ввод сохраняется.

- `ls [-l] [ПУТЬ]`: печатает имя команды и аргументы.
- `cd [ПУТЬ]`: печатает имя команды и аргументы.
- `exit`: завершает работу; дополнительные аргументы вызывают ошибку.

Парсер делит строку через str.split(), кавычки и экранирование не обрабатывает.
Повторные пробелы допустимы. Неизвестные команды, флаги и лишние аргументы
дают сообщение об ошибке, после которого можно продолжать работу.

## Проверка всех параметров скриптами реальной ОС

В Windows запустите по очереди:

```powershell
.\examples\check_config.bat
.\examples\check_overrides.bat
```

В Linux/macOS: `sh examples/check_config.sh` и
`sh examples/check_overrides.sh`. Каждый скрипт передаёт все четыре параметра
CLI. Первый показывает приоритет CLI над JSON, вывод команд и ошибки.
Второй дополнительно проверяет пустое приглашение и прекращение сценария
по exit. Закройте первое окно после проверки, затем запустите второй скрипт.

Дополнительно: `python -m src.main --config config.json` показывает значения
из JSON и запускает scripts/from_json.txt.
`python -m src.main --config missing.json` показывает ошибку чтения.
В scripts/stage2.txt есть комментарии, ls, cd, неизвестная команда,
неверные аргументы и успешная команда после ошибок.

## Структура и функции

- src/main.py: build_shell собирает настройки; main создаёт окно, показывает
  параметры, запускает сценарий и цикл событий.
- src/config.py: AppConfig хранит настройки; parse_args читает CLI;
  load_json_config проверяет JSON; merge_config применяет приоритет;
  resolve_config объединяет источники; iter_script_commands читает сценарий.
- src/shell.py: validate_ls и validate_cd проверяют аргументы; stub_output
  формирует ответ. ShellEmulator.__init__ хранит приглашение и should_exit;
  window_title читает данные ОС; execute разбирает команду;
  _cmd_ls, _cmd_cd и _cmd_exit обрабатывают команды.
- src/gui.py: __init__, _create_output и _create_input создают интерфейс;
  append выводит текст; run_command и _on_enter обслуживают ввод;
  show_config показывает параметры; start_script и _script_step исполняют
  сценарий через очередь событий.
- src/errors.py: EmulatorError представляет пользовательскую ошибку.
- tests/: проверки конфигурации, ошибок запуска, приоритета CLI, сценариев,
  отображения ввода/вывода и exit. GUI проверяется с заменёнными виджетами;
  фактический интерактивный показ выполняется в графической среде.
- examples/: демонстрационные скрипты Windows и Linux/macOS.
- scripts/: стартовые сценарии эмулятора.

Документация функций находится в docstring. Файлы IDE и служебные файлы
Python исключены через .gitignore. Формат коммитов: `тип: описание`.
