# Эмулятор UNIX-подобной оболочки — вариант №26

Практическая работа по конфигурационному управлению.
Приложение реализует графический REPL на Tkinter и виртуальную файловую
систему из CSV. Заголовок окна содержит настоящие имя пользователя и имя
компьютера. Парсер разделяет команду и аргументы по пробельным символам;
кавычки, конвейеры и перенаправления не поддерживаются.

## Требования и запуск

Python 3.10 или новее с установленным Tkinter. Сторонние библиотеки для
приложения и тестов не нужны. Сборка не требуется.
В Windows выберите Python с компонентом Tcl/Tk; в Linux может потребоваться
пакет `python3-tk` из репозитория дистрибутива.

Откройте терминал в корне репозитория:

```powershell
.\run.bat
```

В Linux/macOS:

```sh
sh run.sh
```

При запуске без аргументов эти скрипты используют `config.json` и выполняют
демонстрационный сценарий. Сценарий намеренно содержит ошибочные команды,
чтобы показать их обработку. По завершении окно остаётся открытым.

Для ручного ввода без стартового сценария:

```powershell
.\run.bat --vfs vfs.csv
```

Прямой запуск из корня проекта:

```powershell
python -m src.main --config config.json
python -m src.main --vfs vfs.csv --prompt "student> "
python -m src.main --help
```

В PyCharm создайте конфигурацию запуска модуля `src.main`, укажите корень
этого репозитория как рабочую папку и `--config config.json` как параметры.

## Настройки

| Параметр CLI | Поле JSON | Назначение |
| --- | --- | --- |
| `--vfs` | `vfs` | Путь к CSV с виртуальной файловой системой |
| `--prompt` | `prompt` | Приглашение REPL; по умолчанию `$ ` |
| `--script` | `script` | Путь к стартовому сценарию |
| `--config` | — | Путь к конфигурации JSON |

```json
{
  "vfs": "vfs.csv",
  "prompt": "emu> ",
  "script": "scripts/all_commands.txt"
}
```

Параметры CLI имеют приоритет над JSON, включая пустые строки. Значения JSON
должны быть строками или `null`. Поле `vfs` обязательно для работы с VFS.
Относительные пути отсчитываются от рабочей папки, а не от JSON-файла.
Скрипты `run.bat` и `run.sh` сами переходят в корень проекта.
При запуске отображаются итоговые VFS, prompt, script и путь конфигурации.
Ошибки запуска завершают программу с кодом 2.

## Команды и примеры

Команды вводятся в поле внизу окна и выполняются клавишей Enter.

| Команда | Поведение | Пример |
| --- | --- | --- |
| `ls [-l] [ПУТЬ]` | Дети каталога или файл; `-l`: тип, владелец, байты | `ls -l /home/student` |
| `cd [ПУТЬ]` | Переход; без пути — корень VFS | `cd /home/student` |
| `rev ФАЙЛ` | Разворот символов отдельно в каждой строке | `rev readme.txt` |
| `tail ФАЙЛ` | Последние 10 строк | `tail readme.txt` |
| `tail -n N ФАЙЛ` | Последние N строк; N неотрицательно | `tail -n 3 readme.txt` |
| `tail -N ФАЙЛ` | Краткая форма tail | `tail -5 readme.txt` |
| `who` | Текущий пользователь ОС, компьютер и каталог VFS | `who` |
| `chown ВЛАДЕЛЕЦ ПУТЬ` | Смена владельца узла в памяти | `chown teacher readme.txt` |
| `exit` | Завершение приложения | `exit` |

Пример интерактивного сеанса:

```text
ls /
cd /home/student
rev readme.txt
tail -n 3 readme.txt
who
chown teacher readme.txt
ls -l readme.txt
cd /missing
exit
```

`who` и `chown` прямо указаны в этапах 4 и 5 варианта №26.
Команда `choice` не предусмотрена и не реализована.
Неизвестные команды, неверные флаги, лишние аргументы, отсутствующие пути,
чтение каталогов и двоичных файлов как текста выводят понятные ошибки.

## Формат VFS

CSV содержит столбцы `path,type,content,encoding,owner`:

```csv
path,type,content,encoding,owner
/home/student,dir,,text,student
/home/student/hello.txt,file,Hello,text,student
/bin/data.bin,file,AAEC,base64,root
```

Пути имеют POSIX-формат с `/`. Пропущенные родительские каталоги создаются
в памяти. Тип — `file` или `dir`, кодировка — `text` или `base64`.
Многострочный текст заключается в двойные кавычки по правилам CSV.
Повторные пути и конфликты файла с каталогом отклоняются.
Загрузка атомарная: ошибочный CSV не заменяет текущую VFS.
После чтения исходный файл больше не нужен. `chown` изменяет только память;
повторный запуск восстанавливает владельцев из CSV.

- `vfs_min.csv` — один файл.
- `vfs_nested.csv` — несколько файлов и каталог `/a/b/c`.
- `vfs.csv` — текстовые и двоичные данные, каталог
  `/home/student/docs/project`, примеры для всех команд.

## Сценарии и демонстрация этапов

Стартовый сценарий — UTF-8-файл с одной командой на строку. Пустые строки и
строки, начинающиеся после пробелов с `#`, пропускаются. Видны как введённые
команды, так и их результаты. Ошибка команды не прерывает сценарий;
`exit` прекращает его и закрывает окно.

```powershell
.\run.bat --vfs vfs.csv --script scripts/stage4.txt
.\examples\check_config.bat
.\examples\check_vfs.bat
.\examples\check_overrides.bat
```

Сценарии Windows запускают приложения последовательно: закройте окно,
чтобы перейти к следующему запуску, если сценарий не содержит `exit`.
`check_config.bat` и `check_overrides.bat` проверяют все четыре параметра
CLI; второй также проверяет их приоритет над JSON.
`check_vfs.bat` и `check_overrides.bat` запускают все три варианта VFS.
`scripts/stage1.txt`–`stage5.txt` демонстрируют этапы, включая ошибки.
`scripts/all_commands.txt` объединяет демонстрацию и оставляет окно открытым.

## Тесты

```powershell
python -m unittest discover -s tests -v
```

Тестируются приоритет CLI, ошибки JSON/CSV, вложенность, base64, режимы и
ошибки команд, неизменность CSV после `chown`, выполнение сценариев и вывод
GUI. Проверки GUI подменяют виджеты и не требуют графической среды.

## Структура

```text
src/           исходный код приложения
tests/         модульные и интеграционные тесты
scripts/       команды эмулятора
examples/      сценарии запуска Windows
config.json    пример конфигурации
vfs*.csv       примеры виртуальных файловых систем
run.bat        запуск в Windows
run.sh         запуск в Linux/macOS
```

## История этапов

Пять коммитов отражают последовательность требований:

1. `feat(repl): ...` — окно, парсер, заглушки `ls`/`cd`, `exit`.
2. `feat(config): ...` — CLI, JSON, приоритеты, сценарии и первые тесты.
3. `feat(vfs): ...` — CSV/base64, вложенность, операции в памяти.
4. `feat(commands): ...` — режимы `ls`/`cd`, `rev`, `tail`, `who`.
5. `feat(chown): ...` — изменение владельца в памяти и итоговые проверки.

История восстановлена при исправлении работы, а не является журналом
первоначальной разработки. В первом этапе папка `tests` содержит только
`.gitkeep`; со второго этапа в ней находятся выполняемые тесты.

## Функции и классы

Все функции и методы документированы docstring в исходных файлах.
Ниже приведён справочник, сгруппированный по модулям.

### `__init__.py`

Эмулятор оболочки: вариант №26.


### `config.py`

Аргументы запуска, JSON-конфигурация и стартовые сценарии.

- `AppConfig`: Пути VFS и сценария, приглашение командной строки.
- `parse_args`: Прочитать четыре поддерживаемых параметра командной строки.
- `load_json_config`: Прочитать JSON и проверить типы значений настроек.
- `merge_config`: Применить значения CLI поверх JSON, сохранив пустые строки CLI.
- `resolve_config`: Собрать итоговую конфигурацию с приоритетом аргументов CLI.
- `iter_script_commands`: Читать непустые строки, пропуская комментарии с символом #.

### `errors.py`

Ошибки, которые можно безопасно показать пользователю.

- `EmulatorError`: Ошибка команды, конфигурации или виртуальной файловой системы.

### `gui.py`

Графический REPL и последовательное выполнение стартового сценария.

- `EmulatorGUI`: Окно с журналом диалога и полем ввода команд.
- `EmulatorGUI.__init__`: Создать окно и подключить обработчик ввода.
- `EmulatorGUI._create_output`: Добавить защищённый от редактирования журнал диалога.
- `EmulatorGUI._create_input`: Добавить приглашение, поле ввода и обработчик Enter.
- `EmulatorGUI.append`: Добавить текст в журнал и прокрутить к последней строке.
- `EmulatorGUI.run_command`: Показать ввод, результат или ошибку; обработать завершение.
- `EmulatorGUI._on_enter`: Передать введённую пользователем строку эмулятору.
- `EmulatorGUI.show_config`: Вывести итоговые значения всех четырёх параметров запуска.
- `EmulatorGUI.start_script`: Загрузить сценарий; при ошибке оставить интерактивный REPL.
- `EmulatorGUI._script_step`: Выполнить одну команду сценария без блокирования GUI.

### `main.py`

Точка входа: python -m src.main из корня репозитория.

- `build_shell`: Проверить настройки и загрузить VFS до открытия окна.
- `main`: Запустить GUI; вернуть код 2 при ошибке запуска.

### `shell.py`

Парсер и команды оболочки, предусмотренные вариантом №26.

- `require_count`: Проверить число аргументов команды и показать её синтаксис.
- `parse_ls`: Разобрать ls с необязательными -l и одним путём.
- `parse_count`: Преобразовать количество строк tail в неотрицательное число.
- `parse_tail`: Разобрать tail ФАЙЛ, tail -n N ФАЙЛ и tail -N ФАЙЛ.
- `format_node`: Сформировать краткую или подробную строку ls.
- `ShellEmulator`: Состояние оболочки, реальные имя пользователя и имя компьютера.
- `ShellEmulator.__init__`: Подключить VFS и подготовить состояние сеанса.
- `ShellEmulator.window_title`: Получить заголовок GUI на основе данных реальной ОС.
- `ShellEmulator.execute`: Разделить ввод по пробелам и выполнить указанную команду.
- `ShellEmulator._cmd_ls`: Показать содержимое каталога или сведения об одном файле.
- `ShellEmulator._cmd_cd`: Перейти по пути; без аргументов перейти в корень VFS.
- `ShellEmulator._cmd_rev`: Развернуть символы отдельно в каждой строке текстового файла.
- `ShellEmulator._cmd_tail`: Показать последние N строк; значение по умолчанию равно десяти.
- `ShellEmulator._cmd_who`: Показать пользователя, компьютер и текущий каталог эмулятора.
- `ShellEmulator._cmd_chown`: Изменить владельца файла или каталога в памяти.
- `ShellEmulator._cmd_exit`: Запросить закрытие GUI, проверив отсутствие аргументов.

### `vfs.py`

CSV-файловая система; после загрузки все операции идут в памяти.

- `VFSNode`: Узел: абсолютный путь, тип file/dir, байты, двоичность и владелец.
- `normalize`: Получить нормализованный абсолютный POSIX-путь внутри VFS.
- `decode_content`: Преобразовать текст или base64 в байты без записи на диск.
- `validate_node_fields`: Проверить обязательный путь и допустимые значения типа и кодировки.
- `parse_node`: Проверить одну строку CSV и создать узел файловой системы.
- `VirtualFileSystem`: Дерево узлов и текущий каталог; исходный CSV не изменяется.
- `VirtualFileSystem.__init__`: Создать пустую файловую систему с корневым каталогом.
- `VirtualFileSystem.resolve`: Разрешить путь относительно текущего каталога.
- `VirtualFileSystem.load_csv`: Атомарно загрузить CSV; ошибочный файл не портит текущую VFS.
- `VirtualFileSystem._read_rows`: Проверить заголовок CSV и добавить узлы с номерами строк ошибок.
- `VirtualFileSystem._add_node`: Добавить узел, создав родителей и проверив конфликты типов.
- `VirtualFileSystem.exists`: Проверить существование пути в памяти.
- `VirtualFileSystem.get`: Найти узел или сообщить об отсутствующем пути.
- `VirtualFileSystem.list_dir`: Вернуть файл либо отсортированных непосредственных детей каталога.
- `VirtualFileSystem.change_dir`: Перейти в каталог внутри VFS.
- `VirtualFileSystem.read_text`: Прочитать текстовый файл; каталоги и двоичные файлы отклоняются.
- `VirtualFileSystem.chown`: Изменить владельца узла исключительно в оперативной памяти.
