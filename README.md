## Быстрый запуск

```powershell
.\run.bat

python -m unittest discover -s tests -v
python tools/check_style.py

```

Linux/macOS: `sh run.sh`. Сборка и pip install не требуются.
PyCharm: Module name `src.main`, Parameters `--config config.toml`,
Working directory - корень этапа; интерпретатор Python 3.11 или новее.
Прямой запуск файла src/main.py вместо модуля не используется.
Пример вывода и проверок: [VALIDATION.md](VALIDATION.md).

## Параметры TOML

Все шесть полей обязательны, неизвестные поля запрещены.

| Поле | Значение и проверка |
| --- | --- |
| package | Имя npm либо A-Z в тестовом режиме |
| repository | HTTP(S) URL реестра либо путь JSON относительно TOML |
| test_mode | Только true/false |
| version | Точная версия пакета, например 3.0.1 |
| max_depth | Целое 0..100; корень на глубине 0 |
| filter_substring | Строка без управляющих символов; пустая отключает фильтр |

Ошибки TOML, полей и файлов выводятся в stderr с кодом 2.
На этапе 1 все параметры выводятся как ключ-значение, данные не загружаются.
На этапе 2 выводятся только прямые зависимости точной версии из реестра;
test_mode сообщает, что локальный источник появится на этапе 3.
На этапах 3-5 строится граф DFS. Полная конфигурация больше не печатается.
Фильтр регистрозависим: исключённый узел и его поддерево не анализируются.
Фильтр применяется и к корню. Циклы сохраняются как рёбра без зацикливания.
Узел идентифицируется парой имя/версия. Более короткий путь повторно
раскрывает общий узел, если это позволяет ограничение глубины.

## Границы анализа npm

Анализируется поле dependencies (runtime). devDependencies,
peerDependencies и optionalDependencies не включаются.
Поддерживаются точные версии, теги, ^, ~, x/*, сравнения, OR и интервалы.
Диапазоны prerelease, npm aliases, git/file/URL зависимости отклоняются
с ошибкой, а не заменяются произвольной версией. Точная prerelease допустима.
Выбирается максимальная стабильная версия диапазона без npm/semver.
Корневая версия никогда не заменяется latest. Метаданные кэшируются в памяти.
Сеть имеет тайм-аут 20 секунд и предел ответа 30 МиБ.

## Этапы и демонстрация

1. Валидация TOML и вывод ключ-значение.
2. Прямые зависимости: examples/is-odd.toml, is-even.toml, kind-of.toml.
3. Локальные chain, cycle, diamond, isolated; depth и filter.
4. `--reverse-target C` ищет прямых и транзитивных родителей C.
   Поиск ограничен графом, достижимым из package при заданных глубине/фильтре.
   Это не глобальный поиск по всем пакетам npm. Цель исключается из результата.
   Если цель не указана, используется package; для корня без цикла родителей нет.
5. `--output output/graph` сохраняет DOT и SVG, открывает SVG в браузере.
   `--no-open` отключает открытие для автоматических проверок.
   Режим обратных зависимостей на этапе 5 отсутствует, как требует задание.

Для этапа 5 установите Graphviz и добавьте каталог bin в PATH;
проверка: `dot -V`. Windows: `winget install Graphviz.Graphviz`.
После установки перезапустите терминал/PyCharm. Linux: `sudo apt install graphviz`.
Если dot отсутствует, приложение сохраняет DOT и сообщает об ошибке.
Примеры этапов, ещё не реализованных в этой ветке, здесь не исполняются.

## Формат тестового репозитория (этап 3 и далее)

```json
{"A": {"1.0.0": {"dependencies": {"B": "1.0.0"}}},
 "B": {"1.0.0": {"dependencies": {}}}}
```

Проверяются все имена, версии и ссылки; отсутствующие цели запрещены.
Данные сохраняются в памяти, исходный JSON не меняется.

## Функции и модули текущей ветки


### __init__.py


### config.py

- `Config`: Шесть параметров пользователя и разрешённый путь репозитория.
- `validate_fields`: Проверить полноту и типы параметров до проверки значений.
- `validate_values`: Проверить имя, версию, URL либо путь и строку фильтра.
- `validate_url`: Допустить HTTP(S)-реестр без учётных данных и параметров URL.
- `load_config`: Загрузить TOML; относительный путь считать от файла конфигурации.

### errors.py

- `AppError`: Ошибка конфигурации, репозитория или визуализации.

### main.py

- `arguments`: Прочитать путь TOML и параметры вывода текущего этапа.
- `execute`: Выполнить функциональность только текущего этапа.
- `main`: Запустить приложение; вывести понятную ошибку без traceback.

### registry.py

- `read_json`: Прочитать ограниченный по размеру ответ HTTP и разобрать JSON.
- `dependencies_of`: Прочитать runtime-зависимости; dev/peer/optional не анализируются.
- `Registry`: Реестр npm с кэшем метаданных в памяти на время анализа.
- `__init__`: Сохранить адрес реестра и создать кэш.
- `package`: Загрузить все версии одного пакета, включая scoped-имена.
- `resolve`: Найти точную версию зависимости по её диапазону.
- `dependencies`: Получить прямые зависимости именно запрошенной версии.

### versions.py

- `numbers`: Разобрать стабильную версию без сторонних библиотек.
- `partial`: Развернуть неполную версию или маску в нижнюю и верхнюю границу.
- `compare`: Сравнить тройки версии с заданным оператором.
- `compatible`: Проверить caret или tilde с правилами нулевой основной версии.
- `match_token`: Проверить один точный, масочный или сравнительный диапазон.
- `match_comparator`: Сравнить неполную границу по правилам диапазонов npm.
- `matches`: Поддержать OR, пересечение, дефисный интервал и маски.
- `select_version`: Выбрать максимальную стабильную версию; точные prerelease допустимы.
